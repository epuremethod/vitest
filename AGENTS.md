# Agent notes

## No `exports` map in `@epure/vitest/package.json`

Do not add an `exports` field to `epure-vitest/package.json`, and do not add
subpath entries (such as `@epure/vitest/runtime`) that would need one.

ReScript consumers compile this package with their own `package-specs` and
`suffix`, then import its modules by file path, for example
`@epure/vitest/src/EpureVitest.res.js` (in-source) or
`@epure/vitest/lib/es6/src/EpureVitest.res.js` (not in-source). Any `exports`
map blocks the paths it does not list, and Node fails with
`ERR_PACKAGE_PATH_NOT_EXPORTED`. It was removed for this in 0.6.1, came back
with the rename, and has been removed again.

Code generated by the plugin imports only from `"@epure/vitest"` (the main
entry) and `"vitest"`.

## Ask before adding structure

Do not introduce new entry points, subpaths, globals or indirection layers
that were not asked for. Propose them first.
